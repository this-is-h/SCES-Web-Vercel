# 错误处理规范（前端）

## 目标

- 用户级错误：可预期、可恢复或与用户操作相关，需要友好提示。
- 系统级错误：不可预期、开发/运行时异常，只在控制台记录，不打扰用户。

## 统一入口

- 使用 `reportError(err, context)` 记录错误与上下文（默认系统级）。
- 全局仅对“资源/模块加载失败（chunkLoad）”与显式标记的“用户级错误”做 UI 提示。

## 用户级错误（需要提示）

适用场景：

- 表单校验失败、必填项缺失
- 用户触发的导入/导出/保存失败（例如权限不足、数据不完整）
- 明确可操作的网络错误（例如提示重试、刷新、检查网络）

推荐做法：

- 在触发点直接提示（如页面按钮操作的 `try/catch` 中）。
- 或构造用户级错误后交给全局提示：
  - `reportError(createUserError({ title, userMessage }), { operation })`

## 系统级错误（仅控制台）

适用场景：

- 组件渲染异常、未处理 Promise 拒绝、不可预期的运行时错误
- 浏览器资源加载噪声（非 ErrorEvent 的 error 事件）

处理方式：

- `reportError(err, context)` 记录到控制台（必要时带上 source/component/info 等上下文）。
- 不弹出通用错误通知，避免造成“持续弹窗”体验问题。

## 全局提示的最小化原则

- 只在用户可行动时提示：刷新、重试、检查网络、修复输入等。
- 相同错误短时间内去重，避免重复通知干扰操作。
