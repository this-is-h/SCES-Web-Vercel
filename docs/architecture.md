# 预览端架构

## 模块边界

| 模块       | 位置                                                      | 职责                                              |
| ---------- | --------------------------------------------------------- | ------------------------------------------------- |
| 页面与路由 | `src/views/`、`src/router/`                               | 学生、班级、年级工作流                            |
| 界面状态   | `src/stores/`                                             | 当前学生、数据列表、选择与删除状态                |
| 文件访问   | [FileSystemManager.js](../src/utils/FileSystemManager.js) | 目录授权、权限恢复、文件读写                      |
| 学生存储   | [studentStorage.js](../src/utils/studentStorage.js)       | 学期/班级归属校验、信息归一化、材料保存与嵌入导出 |
| 交换容器   | [dyfFile.js](../src/utils/dyfFile.js)                     | `.dyf` 加解密、帧校验与导入导出                   |
| 表格导出   | `src/utils/excel/`                                        | 模板映射、工作簿和公式生成                        |
| 运行配置   | `public/configs/`                                         | 学期、类别、分值及单位配置                        |

本仓为静态 Web 应用，不包含 SQL 数据库或在线授权服务。在线管理端、微信端与服务端分别由其他仓库维护，不应把本仓预览逻辑当作服务端契约实现。

## 本地持久化

用户目录通过 File System Access API 授权；localforage 保存目录句柄，恢复句柄后仍须查询读写权限。取消授权、目录不可用和权限被撤销都需要按文件操作失败处理。

学生信息与证明文件分别落盘，由学生存储模块统一处理目录、身份与班级归属。Pinia 状态和目录句柄缓存不能代替文件备份；成功的内存更新也不等于落盘成功。

## 文件格式

当前导出格式为 `.dyf` v6，默认帧大小 4 MiB：头部和清单描述结构，学生 JSON 与二进制材料按学生分组写入独立 AES-GCM 帧。读取时校验版本、序号、长度、认证信息和清单，不能忽略损坏帧继续导入。

旧版 v3 内联 JSON 和更早的裸学生 JSON 保留兼容入口；v5 容器不支持。旧内联路径存在整段 JSON 与字符串内存开销，代码设置 496 MiB 输入上限，不代表该尺寸在所有设备上都可用。v6 的分帧设计也不构成浏览器大文件容量已经验收的证明。

本仓 v6 与 SCES-Shared 的 v2 容器不是同一格式。跨端互通必须以实际解析器和互操作测试为准，不能只检查 `.dyf` 扩展名。

## 附件与回归

内联附件导出的 Base64 分块按 3 字节边界切分，避免中间块填充截断后续内容；空附件允许空 payload。该兼容路径最终仍组装 Data URL，不能当作无界流式存储。

测试入口：

- [dyfFile.container.test.mjs](../tests/dyfFile.container.test.mjs)：容器往返、分帧校验与旧格式。
- [studentStorage.test.mjs](../tests/studentStorage.test.mjs)：附件字节完整性与空文件。

涉及存储或格式变更，需保留已有合法文件的读取能力或明确拒绝不支持版本，并覆盖跨块边界和损坏输入。运行 `pnpm test:unit run`、`pnpm type-check`、`pnpm lint` 与 `pnpm build`；涉及权限、目录选择、实际大文件和 Excel 公式时另做浏览器/导出验收。
